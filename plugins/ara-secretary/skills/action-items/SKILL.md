# 액션 아이템 추출

회의에서 누군가 하기로 한 일을 빠짐없이 뽑아 표로 정리한다. 원문에 근거한 것만 쓴다. 정해지지 않은 담당자와 기한은 채우지 않고 [미정]으로 드러낸다.

## 0. 설정 확인

단독 실행일 때만 한다. minutes 스킬에서 이어서 실행했으면 minutes가 이미 확인했으므로 건너뛴다.

`~/.claude/ara-secretary/config.json`이 없으면 사용자에게 "처음 실행이라 Notion 저장 설정부터 할게요"라고 알리고 `${CLAUDE_PLUGIN_ROOT}/skills/setup/SKILL.md`를 읽어 그대로 따른다. 설정이 끝나면 1장으로 돌아온다. 사용자가 설정을 미루겠다고 하면 Notion 저장 없이 진행하고 7장에서 로컬 저장만 제안한다.

## 1. 입력 받기

이 스킬은 두 가지 방식으로 실행된다.

| 실행 방식 | 입력 | 할 일 |
| --- | --- | --- |
| minutes 스킬에서 이어서 실행 | minutes 스킬이 정리한 녹취록과 회의록 3장(안건별 논의) | 바로 2장으로 간다. 관련 안건은 회의록의 절 번호(3.1, 3.2)로 쓴다 |
| 단독 실행 | 녹취록 또는 이미 작성된 회의록 | 녹취록이면 `${CLAUDE_PLUGIN_ROOT}/skills/minutes/SKILL.md`의 1장(입력 받기)과 2장(입력 정리)을 먼저 따른다. 회의록이면 그대로 읽는다. 관련 안건은 안건 이름으로 쓴다 |

## 2. 액션 아이템 찾기

정리한 녹취록을 처음부터 끝까지 읽으며 아래 발언을 모두 후보로 잡는다. 결정 사항만 보지 말고 논의 중간의 발언까지 본다.

1. 명확한 배정: "민수 님이 맡아 주세요", "이건 아라 님 담당으로 할게요"
2. 스스로 맡겠다는 말: "제가 할게요", "제가 정리해서 공유할게요"
3. 가벼운 약속: "제가 확인할게요", "한번 알아볼게요", "~해 볼게요", "물어볼게요", "찾아볼게요"
4. 요청과 수락: "이거 좀 봐 주실 수 있어요?"에 "네"로 답한 경우. 담당자는 수락한 사람이다
5. 담당자 없는 할 일: "누가 이거 정리해야겠네요", "다음 회의 전까지 확정해야 해요"

액션 아이템으로 잡지 않는 것:

- 이미 회의 중에 끝낸 일("방금 공유했어요")
- 의견이나 바람만 있고 할 일이 없는 말("이렇게 되면 좋겠네요")
- 회의 밖에서 이미 진행 중이라고 보고만 한 일. 다만 스크럼에서 "오늘 할 일"로 말한 것은 잡는다

같은 일이 회의 중 여러 번 나오면 하나로 합친다. 마지막에 나온 담당자와 기한을 따른다.

## 3. 표 작성

모든 액션 아이템을 아래 표 하나로 정리한다. 열 순서와 이름을 바꾸지 않는다.

```markdown
| 담당자 | 할 일 | 기한 | 관련 안건 |
| --- | --- | --- | --- |
| 김민수 | 로그인 오류 재현 환경 정리해서 팀 채널에 공유하기 | 2026-10-10 | 3.1 |
| 조아라 | 디자인 시안 수정 일정 디자인팀에 확인하기 | [미정] | 3.2 |
| [미정] | 다음 분기 예산안 초안 작성하기 | 다음 회의 전 | 3.3 |
```

열별 규칙:

1. 담당자
   - 원문에서 맡겠다고 했거나 배정받은 사람의 이름을 쓴다. 이름은 minutes 스킬 2장에서 통일한 이름을 따른다.
   - 회의에서 정하지 않았으면 `[미정]`으로 쓴다. 문맥상 누가 할지 짐작이 가도 채우지 않는다.
   - 여러 명이면 쉼표로 나열한다. 주 담당자가 언급됐으면 맨 앞에 쓴다.
2. 할 일
   - "~하기" 형태로 끝낸다.
   - 결과물이 보이도록 구체적인 동사를 쓴다. "확인", "검토", "처리"처럼 뜻이 넓은 말만 쓰지 않고 무엇을 어디까지 할지 붙인다.
     - 고치기 전: `API 확인하기`
     - 고친 후: `결제 API 응답 시간이 2초를 넘는 원인 확인하기`
   - 원문에 없는 세부 내용을 지어내 구체화하지 않는다. 원문이 모호하면 원문 범위 안에서만 쓰고 끝에 `[확인 필요]`를 붙인다.
3. 기한
   - 날짜가 나오면 `YYYY-MM-DD`로 쓴다. "금요일까지", "다음 주 수요일"처럼 상대적인 표현은 회의 일시를 기준으로 날짜를 계산한다. 회의 일시를 모르면 원문 표현을 그대로 쓴다.
   - "다음 회의 전", "배포 전"처럼 날짜가 아닌 기준은 그대로 쓴다.
   - 회의에서 정하지 않았으면 `[미정]`으로 쓴다. "빨리", "곧"은 기한이 아니다. `[미정]`으로 쓴다.
4. 관련 안건
   - minutes 스킬에서 이어서 실행했으면 회의록 절 번호를, 단독 실행이면 안건 이름을 쓴다.
   - 특정 안건에 속하지 않으면 `기타`로 쓴다.

정렬: 담당자가 정해진 항목을 담당자 이름 순으로 먼저 두고, 담당자가 `[미정]`인 항목을 맨 아래에 둔다.

## 4. 정해야 할 항목

표에 `[미정]`이 하나라도 있으면 표 바로 아래에 이 목록을 만든다. 없으면 만들지 않는다.

```markdown
### 정해야 할 항목

- 담당자 미정: 다음 분기 예산안 초안 작성하기 (3.3)
- 기한 미정: 디자인 시안 수정 일정 디자인팀에 확인하기 (조아라, 3.2)
```

- 담당자 미정 항목을 먼저, 기한 미정 항목을 다음에 쓴다.
- 담당자와 기한이 둘 다 미정이면 `담당자, 기한 미정:`으로 한 줄에 쓴다.
- 각 줄 끝 괄호에는 이미 정해진 정보(담당자, 관련 안건)를 넣는다.

## 5. 표시 구분

- `[미정]`: 회의에서 정하지 않은 담당자와 기한. 회의 뒤에 사람이 정해야 한다.
- `[확인 필요]`: 녹취록이 불분명해서 원문을 다시 봐야 하는 것. 예를 들어 누가 맡겠다고 했는지 화자가 불분명한 경우다.

두 표시를 섞지 않는다. 담당자를 정하지 않은 것은 `[미정]`, 정했는데 누군지 알아들을 수 없는 것은 `[확인 필요]`다.

## 6. 점검

내보내기 전에 확인한다.

- 표의 모든 항목이 원문 발언에 근거하는가.
- "제가 확인할게요", "~해 볼게요" 같은 가벼운 약속을 빠뜨리지 않았는가. 녹취록에서 "할게요", "볼게요", "드릴게요"로 끝나는 발언을 다시 훑는다.
- 할 일이 모두 "~하기"로 끝나는가.
- `[미정]`이 있는데 정해야 할 항목 목록이 빠지지 않았는가.
- 원문에 없는 담당자, 기한, 세부 내용을 채우지 않았는가.

## 7. 결과 전달

minutes 스킬에서 이어서 실행했으면 표와 정해야 할 항목을 회의록 6장에 넣고 끝낸다. 따로 출력하거나 저장하지 않는다. Notion 저장은 minutes 스킬이 확인을 받은 뒤 8장 규칙으로 한다.

단독 실행이면:

1. 표와 정해야 할 항목을 대화에 출력하고 짧게 덧붙인다: 액션 아이템 개수, `[미정]` 개수, `[확인 필요]` 위치.
2. 묻는다: "Notion에 저장할까요?" 설정이 없으면 이 질문 대신 3번으로 간다.
   - 예: 연결할 회의록을 묻는다. "이미 Notion에 있는 회의록에 연결할까요, 연결 없이 저장할까요?" 연결한다면 회의록 DB에서 제목이나 날짜로 검색해 후보를 보여 주고 고르게 한다. 그다음 8장대로 저장한다.
   - 사용자가 표를 고쳐 달라고 하면 고친 표를 다시 보여 주고 다시 묻는다.
3. 아니요이거나 설정이 없으면 로컬 저장을 제안한다. 원하면 같은 폴더에 `<원본 파일 이름>_액션아이템.md`로 저장한다. 붙여 넣은 텍스트였으면 현재 작업 폴더에 저장한다.

## 8. Notion 저장

설정 파일의 `action_items_db`에 액션 아이템을 한 줄에 페이지 하나씩 만든다. 속성 이름은 setup 스킬 5장을 따른다. 저장은 사용자가 확인한 뒤에만 한다.

### 8.1 담당자 찾기

저장 전에 Notion 워크스페이스 사용자 목록을 한 번 가져온다.

- 표의 담당자 이름이 Notion 사용자의 이름과 정확히 같을 때만 그 사람을 넣는다. 띄어쓰기만 다른 경우는 같은 이름으로 본다.
- 부분 일치(`민수`와 `김민수`), 영문과 한글 표기 차이, 같은 이름의 사용자가 둘 이상인 경우는 넣지 않고 비운다. 짐작으로 고르지 않는다.
- 담당자가 여러 명이면 사람마다 따로 판단한다. 찾은 사람만 넣는다.
- 찾지 못한 사람은 `담당자`에 넣지 않고 `담당자 메모`에 이름을 텍스트로 적는다(8.2). 팀원이 Notion에 없어도 누가 맡았는지 남기기 위해서다.
- 찾지 못한 담당자는 8.4 보고에 넣는다.

### 8.2 속성 채우기

| 속성 | 값 |
| --- | --- |
| 할 일 | 표의 할 일. `[확인 필요]` 표시는 그대로 둔다 |
| 담당자 | 8.1에서 찾은 사람. 없거나 `[미정]`이면 비운다 |
| 담당자 메모 | 8.1에서 찾지 못한 담당자 이름. 여러 명이면 쉼표로 나열한다. `[미정]`이면 `미정`. 모두 찾았으면 비운다 |
| 기한 | 표의 기한이 `YYYY-MM-DD`일 때만 넣는다 |
| 기한 메모 | 기한이 날짜가 아닐 때 표의 원문 표현(`다음 회의 전`, `금요일까지`)을 넣는다. `[미정]`이면 `미정`. 날짜로 넣었으면 비운다 |
| 상태 | `할 일`. 설정의 `status_type`에 맞는 타입으로 넣는다 |
| 관련 회의 | 연결할 회의록 페이지. 연결 없이 저장하기로 했으면 비운다 |

`[미정]` 표시 문자열을 담당자나 기한 속성에 넣지 않는다. 비워 두는 것이 미정을 뜻한다.

### 8.3 실패 처리

- 한 줄씩 만들고 성공한 페이지 링크를 기억한다.
- 일부가 실패하면 멈추고 성공한 것과 실패한 것(할 일, 오류 내용)을 알린다. 실패한 것만 다시 시도할지 묻는다. 성공한 것을 다시 만들지 않는다.
- 설정의 DB를 찾을 수 없다는 오류(삭제, 권한 없음)면 저장을 멈추고 `/ara-secretary:setup`으로 설정을 다시 하라고 안내한다.
- 속성이 없다는 오류면 어느 속성인지 알리고 setup으로 DB 구조를 맞추라고 안내한다. 이전 버전으로 만든 DB에는 `담당자 메모`가 없을 수 있다.

### 8.4 보고

- 저장한 액션 아이템 개수
- 담당자를 `담당자 메모`에 텍스트로 넣은 항목: `할 일 (김민수, Notion에서 찾지 못함)` 형식. `[미정]`이라 `미정`으로 넣은 것과 구분한다
- 기한을 비우고 기한 메모에 넣은 항목
- 단독 실행이면 액션 아이템 DB 링크
