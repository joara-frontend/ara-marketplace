# Notion 저장 설정

회의록 DB와 액션 아이템 DB를 정하고 `~/.claude/ara-secretary/config.json`에 기록한다. 이 파일은 minutes, action-items 스킬이 처음 실행될 때 설정 파일이 없으면 직접 읽어서 따르기도 한다.

## 1. 설정 파일

위치: `~/.claude/ara-secretary/config.json` (Windows에서는 `%USERPROFILE%\.claude\ara-secretary\config.json`)

플러그인 폴더는 업데이트 때 덮어써지므로 설정은 반드시 이 경로에 쓴다. `${CLAUDE_PLUGIN_ROOT}` 안에 쓰지 않는다.

```json
{
  "version": 1,
  "notion": {
    "parent_page_id": "<DB를 둔 페이지 ID>",
    "minutes_db": { "id": "<회의록 DB ID>", "url": "<회의록 DB 링크>" },
    "action_items_db": { "id": "<액션 아이템 DB ID>", "url": "<액션 아이템 DB 링크>" },
    "status_type": "status"
  },
  "created_at": "YYYY-MM-DD"
}
```

- `status_type`: 액션 아이템 DB의 상태 속성 타입. `status` 또는 `select`. 4장에서 실제로 만든 타입을 적는다.
- 설정 파일이 이미 있으면 내용을 보여 주고 무엇을 바꿀지 묻는다. 바꾸지 않은 값은 그대로 둔다.
- 설정 파일을 읽을 수 없거나 `version`이 1이 아니면 내용을 보여 주고 새로 설정할지 묻는다. 묻지 않고 덮어쓰지 않는다.

## 2. Notion 연결 확인

Notion MCP 도구가 있는지 확인한다. 플러그인의 `notion` 서버(`.mcp.json`)나 claude.ai에서 연결한 Notion 커넥터 중 연결된 쪽을 쓴다. 둘 다 연결되어 있으면 아무 쪽이나 하나만 쓰고 섞지 않는다.

- 사용할 수 있는 Notion 도구가 없거나 호출이 인증 오류로 실패하면 아래처럼 안내하고 멈춘다. 설정 파일을 만들지 않는다.

  > Notion에 아직 연결되어 있지 않아요. `/mcp`를 입력하고 목록에서 notion을 골라 로그인한 뒤 다시 실행해 주세요.

- 연결되어 있으면 현재 로그인한 Notion 사용자 이름을 알려 주고 다음으로 간다.

## 3. DB를 둘 위치 정하기

1. 묻는다: "회의록 DB와 액션 아이템 DB를 둘 Notion 페이지 이름이나 링크를 알려 주세요. 팀 캘린더로 쓰려면 팀원이 볼 수 있는 페이지를 고르세요."
2. 링크를 받으면 그 페이지를 가져온다. 이름을 받으면 Notion 검색으로 후보를 찾아 제목과 상위 경로를 번호 목록으로 보여 주고 고르게 한다. 후보가 없으면 다시 묻는다.
3. 고른 페이지 아래에 이미 DB가 있는지 본다.
   - 이름이 `회의록`, `액션 아이템`인 DB가 있으면 그것을 연결할지 묻는다. 팀원이 이미 만들어 둔 DB를 쓰는 경우다.
   - 연결하기로 하면 5장의 구조와 비교한다. 빠진 속성이나 타입이 다른 속성을 목록으로 보여 주고, 추가할지 묻는다. 기존 속성을 지우거나 타입을 바꾸지 않는다.
   - 다른 이름의 DB를 쓰고 싶다고 하면 링크를 받아 같은 방식으로 비교한다.
   - 연결할 DB가 없으면 4장으로 새로 만든다. 만들기 전에 "<페이지 이름> 아래에 회의록 DB와 액션 아이템 DB를 새로 만들게요"라고 알리고 확인받는다.

## 4. DB 새로 만들기

5장 구조대로 만든다. 순서를 지킨다.

1. 회의록 DB를 만든다. `액션 아이템` 속성은 아직 만들지 않는다.
2. 액션 아이템 DB를 만든다. `관련 회의` 속성을 회의록 DB와의 양방향 Relation으로 만들고, 반대편 속성 이름을 `액션 아이템`으로 한다.
   - 도구가 양방향 Relation을 한 번에 만들지 못하면 단방향으로 만든 뒤 회의록 DB에 `액션 아이템` Relation을 따로 추가한다.
3. `상태` 속성은 상태(status) 타입으로 만들고 옵션을 `할 일`, `진행 중`, `완료`로 맞춘다.
   - 상태 타입을 만들 수 없거나 옵션을 지정할 수 없으면 선택(select) 타입으로 같은 세 옵션을 만들고 `status_type`을 `select`로 기록한다. 사용자에게 바꾼 이유를 한 줄로 알린다.
4. 회의록 DB에 `날짜` 기준 캘린더 보기를 추가한다.
   - 보기를 만드는 도구가 없거나 실패하면 만들지 말고 7장 안내에 포함한다.
5. 만든 뒤 두 DB를 다시 가져와 5장 구조와 맞는지 확인한다.

## 5. DB 구조

속성 이름을 바꾸지 않는다. minutes, action-items 스킬이 이 이름을 그대로 쓴다.

회의록 DB (이름: `회의록`)

| 속성 | 타입 | 옵션 |
| --- | --- | --- |
| 제목 | title | |
| 날짜 | date | |
| 회의 유형 | select | 스크럼, 기획 회의, 회고, 그 밖의 회의 |
| 참석자 | multi_select | 저장할 때마다 이름이 추가된다 |
| 액션 아이템 | relation | 액션 아이템 DB의 `관련 회의`와 양방향 |

액션 아이템 DB (이름: `액션 아이템`)

| 속성 | 타입 | 옵션 |
| --- | --- | --- |
| 할 일 | title | |
| 담당자 | people | |
| 기한 | date | |
| 기한 메모 | rich_text | 날짜로 바꿀 수 없는 기한의 원문 표현 |
| 상태 | status (안 되면 select) | 할 일, 진행 중, 완료 |
| 관련 회의 | relation | 회의록 DB와 양방향 |

## 6. 설정 저장

1. `~/.claude/ara-secretary/` 폴더가 없으면 만든다.
2. 1장 형식으로 `config.json`을 쓴다. ID는 Notion이 돌려준 값을 그대로 쓰고 지어내지 않는다.
3. 쓴 파일을 다시 읽어 JSON으로 읽히는지 확인한다.

## 7. 결과 보고

짧게 알린다.

- 연결한 Notion 계정
- 회의록 DB 링크, 액션 아이템 DB 링크, 새로 만들었는지 기존 것을 연결했는지
- 상태 속성 타입이 select로 바뀌었다면 그 사실
- 캘린더 보기를 못 만들었다면 이 안내:

  > 회의록 DB를 열고 보기 추가에서 캘린더를 고른 뒤, 기준 속성을 날짜로 정해 주세요.

- minutes나 action-items 실행 중에 설정으로 들어왔다면, 설정이 끝난 뒤 원래 작업으로 돌아간다고 알리고 이어서 진행한다.
